# Calculated CSV export TDD evidence

The explicitly requested tdd:tdd workflow is used. No Superpowers workflow is used. This change owns only csv.hpp/csv.cpp, csv_tests.cpp and this document. The generic writeCsv API continues to serialize raw cell input; the new csvValuesSnapshot helper prepares a separate values snapshot for export.

The calculation result contract is the existing native engine format: integer revision, status `ok`, and typed values with sheet/row/col/type/value. Types are number, text, boolean, error and empty. Formula-error diagnostics do not invalidate an otherwise completed calculation; their typed error text is an exportable cell value.

The first test describes `=6*7` exported as `42` from a typed numeric result, actual CSV file output, and an unchanged canonical workbook. RED: the configured csv_tests build failed because csvValuesSnapshot was deliberately absent. The minimal first implementation formats the numeric result independently of source formula text.

The numeric formula/file test passed under ASan+UBSan. A selected-sheet spill test then failed `CSV values include generated spill cells outside sparse source cells`. The helper now overlays typed values onto a sorted sparse-cell map, adding generated spill coordinates. The same test passed, including preservation of an unselected sheet, round-trip double precision and a JSON integer above the exact-double range without rounding it through double.

The scalar-value test failed `CSV typed values preserve literal strings booleans errors empties and multiline text`. A typed overlay now preserves text/error strings verbatim, writes booleans as TRUE/FALSE and empties as empty fields. Literal raw inputs without a calculated entry drop exactly one semantic apostrophe escape; typed text is never stripped. The first implementation run caught a moved-from JSON evaluation-order error; extracting a cell's coordinate before moving it into the map corrected that error. The unchanged acceptance test then passed.

The final validation test reported all ten unrejected cases before implementation: stale revision, missing selected formula result, cancelled calculation, absent status, noninteger revision, duplicate result coordinate, out-of-bounds coordinate, fractional coordinate, invalid empty payload and nonfinite number. It now passes with explicit status/revision/coordinate/payload checks and a required result entry for each selected-sheet formula. Formula-produced empty/error values count as present results. Missing results on an unselected sheet do not prevent exporting the chosen sheet; the spill/isolation test covers this. Unknown selected sheet IDs are rejected.

Usage: call `csvValuesSnapshot(workbook, calculated, selectedSheetId)`, then `writeCsv(destination, prepared, selectedSheetId)`. The returned snapshot retains all sheets and metadata, modifies only the selected sheet's isolated CSV inputs, and must be used only as export preparation. Formula-looking typed text is intentional CSV field content, so the prepared copy should not be recalculated as a workbook. No calculation dependency was added and writeCsv remains unchanged. The UI caller owns calculation, export-path handling and dirty-state behavior.

Final verification after the helper froze: `cmake --build /tmp/tigersheets-io-asan --target csv_tests ooxml_tests session_tests -j2` and `ASAN_OPTIONS=detect_leaks=0 ctest --test-dir /tmp/tigersheets-io-asan -R '^(csv|ooxml|session)_tests$' --output-on-failure` passed 3/3 tests in 0.17 seconds with AddressSanitizer+UBSan. LeakSanitizer is disabled because the environment does not permit its ptrace workflow. `g++ -std=c++20 -Wall -Wextra -Wpedantic -Werror -fsyntax-only -Iinclude src/csv.cpp tests/csv_tests.cpp` also passed. No additional production refactor was needed.
