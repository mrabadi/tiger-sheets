# Formula draft interaction and worksheet focus

`WorksheetView` now paints colored outlines for references in the active in-cell or formula-bar draft. It uses the lexical reference parser, skips external and other-sheet references, and accepts case-insensitive current-sheet qualifiers through the public `setCurrentSheetName(const QString&)` setter. Painting clips each range edge to the viewport without expanding cell ranges or drawing giant rectangles. Whole-row/whole-column references remain bounded after scrolling far into the worksheet. Draft cancellation removes the outlines. Painting does not navigate or mutate the canonical workbook.

Bare arrow keys after `=` or an operand delimiter choose a neighboring reference. Further arrows move the pointed reference; Shift arrows extend a range from its anchor. Pointing keeps the original edit destination and only changes the editor draft until the usual commit. Formula-bar and in-cell editors share this behavior. F2 toggles keyboard point mode versus ordinary text-cursor editing. Completion's `beforeEditorKey` hook always receives the key first, so its arrow handling takes precedence. Existing mouse pointing and commit/cancel paths remain in use.

The cell delegate preserves modified editor text, cursor and live formula-bar mirror when calculation `dataChanged` arrives. Worksheet destruction closes the active editor while derived members are alive, then disconnects editor/delegate callbacks and the formula-bar event filter before base-class teardown. This avoids delayed heap corruption when a focused view is destroyed and its replacement is constructed. The current cell also has a forest (`#245648`) outline; no fill handle or unimplemented fill gesture is shown, and native selection fills remain painted by QTableView.

## Executed RED → GREEN cycles

The independent harness `/tmp/tigersheets-worksheet-ux` links only worksheet_view, grid, session, references and Qt Widgets/Test. Shared MainWindow/CMake/workspace UX tests were not edited.

- Dirty entry RED: a real native cell editor's modified draft/caret was overwritten by `WorksheetModel::setCalculated`/`dataChanged`. A delegate `setEditorData` guard made the same test pass and retained canonical isolation.
- Outline RED: the active `=SUM(B1:B3)` draft produced no visible blue worksheet outline. Native viewport painting then passed the focused pixel test and cancellation check. Parent's existing MainWindow outline test had independently failed for the same user-visible behavior.
- Keyboard RED: Right after `=SUM(` did not insert a neighboring reference. Arrow/Shift range handling and F2 mode switching then passed for both native editors; completion consumption and unchanged canonical snapshot/current index are asserted.
- Teardown RED: destroying a focused standalone view appeared to return, but a subsequent fixture allocation aborted with `malloc(): unaligned tcache chunk detected`. Closing the editor and disconnecting callbacks before derived-member destruction removed the failure. Tests destroy views without manual cancel, preserve canonical state, and construct replacements; final coverage includes both modified and unmodified editor flags.
- Border RED: after correcting teardown, the focused pixel test failed because the active cell lacked a forest border. Painting only that border made the same test pass.

The initial dirty test fixture needed explicit cancellation during assertion-unwind teardown to preserve its meaningful dirty-entry RED; the separate standalone-close regression intentionally omits that fixture cancellation. An early teardown assertion demanding immediate QPointer nullness was removed because Qt may defer editor deletion; it was not counted as meaningful RED. The retained teardown RED is the actual allocator corruption on replacement allocation.

## Verification

The final normal `worksheet_entry_tests` passes dirty-entry, draft-outline, keyboard, teardown, active-border and boundary cases. Boundary coverage includes current-sheet name matching, excluding foreign/external/literal references, a whole-column outline scrolled past row 200,000, and whole-row viewport clipping. Normal tests use the Qt offscreen platform; its size-hint warnings are benign. Host MainWindow completion, command, transaction and persistence integration is checked by the parent task.

Both final focused binaries also passed under a fresh isolated AddressSanitizer/UndefinedBehaviorSanitizer build with `-fsanitize=address,undefined -fno-omit-frame-pointer` and `ASAN_OPTIONS=detect_leaks=0`; the complete test run reported no sanitizer diagnostics. Leak detection is disabled for the existing environment limitation. The normal and sanitizer commands used `QT_QPA_PLATFORM=offscreen`. Durable raw evidence is `docs/validation/worksheet-entry-tdd.log`; independent build logs remain under `/tmp/tigersheets-worksheet-ux`. Production and test sources are frozen after these checks.

## Formula bar destroyed before its worksheet view

The parent's full MainWindow sanitizer run exposed a second destruction order absent from the initial stack fixture: a sibling formula bar is deleted while its WorksheetView remains alive. QPointer is cleared at QObject destruction, so during the preceding QWidget base destructor it can still hold an object that is no longer a QLineEdit. The event filter's original identity comparison dereferenced `QPointer<QLineEdit>` and triggered an invalid downcast.

A new focused `bar_first` case creates the formula bar on the heap, edits a draft, deletes the bar before its live view, then deletes the view and creates a replacement. Before the production fix, the isolated sanitizer command with `UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1` failed at `qpointer.h:77`, through `WorksheetView::eventFilter`, reporting that the object was QWidget rather than QLineEdit. Normal execution alone was not treated as sufficient evidence for this lifetime regression.

The minimal fix inspects the current event object with `qobject_cast<QLineEdit*>` before any typed QPointer identity comparison and uses that validated editor for key handling. QWidget base-destruction events bypass the QLineEdit-specific path. No public API or unrelated behavior changed. The selected sanitizer regression, full seven-case isolated sanitizer suite, and full normal suite then passed with no sanitizer diagnostics. Raw RED/GREEN evidence is retained in `docs/validation/worksheet-entry-bar-first-tdd.log`. The sanitizer run enabled ASan/UBSan, disabled leak detection for the environment limitation, and halted on UBSan errors. Parent MainWindow sanitizer integration is rerun separately.

## Unmodified editor caret and selection during calculation

The focused `clean_selection` regression opens canonical `=1+2`, changes only the caret/selection (leaving `isModified()==false`), and delivers a calculation through `WorksheetModel::setCalculated`. Before the fix it failed because delegate refresh reset the selection/caret even though the edit source was unchanged. The minimal delegate guard now also skips `setEditorData` when the editor already contains the index's EditRole text. Initial nonempty canonical source still populates an empty new editor, and a genuinely different unmodified source can still refresh. The selected regression, full eight-case normal suite, and full eight-case ASan/UBSan suite passed. The latter used `UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1` with the existing sanitizer/offscreen environment and had no sanitizer diagnostics. Raw evidence is `docs/validation/worksheet-entry-clean-selection-tdd.log`. No public API changed.
