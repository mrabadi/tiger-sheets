# Install TigerSheets on Ubuntu

The current Ubuntu amd64 development installer is `build-release/tiger-sheets_0.3.0~dev.4_amd64.deb`, generated by the rebuild commands below. It includes [clipboard, sheet-tab, selection and save-status fixes](TDD_WORKSHEET_INTERACTIONS.md), [number-format options](TDD_CELL_FORMATS.md), [worksheet right-click menus](CONTEXT_MENUS.md), and [forecasts and what-if workflows](FORECAST_WORKFLOWS.md).

From the repository directory, install or upgrade:

```sh
sudo apt install ./build-release/tiger-sheets_0.3.0~dev.4_amd64.deb
```

APT recognizes this version as an upgrade from `0.3.0~dev.3` and installs required runtime dependencies. These instructions target Ubuntu 22.04 or later on amd64.

Launch **TigerSheets** from the application menu or run `tiger-sheets`. Use `tiger-sheets --demo` to open the editable financial example, or `tiger-sheets --version` to check the installed version. XLSX, XLSM and CSV associations, launcher icons, the report worker and the macro worker are included. Ordinary local editing does not require Codex. Uninstall with `sudo apt remove tiger-sheets`.

This is development software with incomplete Excel/VBA compatibility. The [current validation record](TDD_WORKSHEET_INTERACTIONS.md) describes the checks actually executed for this revision and their limits. Complete Excel compatibility and actual Microsoft Excel reopen/VBA execution remain unverified.

## Rebuild and inspect

After configuring and building the optimized application, use the explicit development package configuration:

```sh
cpack --config build-release/CPackDevelopmentConfig.cmake -B build-release
python3 tools/verify_development_package.py \
  'build-release/tiger-sheets_0.3.0~dev.4_amd64.deb' \
  --expect-version '0.3.0~dev.4' \
  --output 'build-release/tiger-sheets_0.3.0~dev.4_amd64.deb.validation.json'
```

The validator extracts the package privately, checks its metadata, desktop/MIME/icons, ELF runtime paths and Qt platform dependencies, runs the staged worker protocols and performs a read-only APT upgrade simulation. It does not install or modify system packages. Its offscreen application probe uses this host's installed runtime; it does not qualify a clean-machine installation, native keyboard input or accessibility.

The local audit is written beside the development package. User documentation is included, but generated `docs/validation` archives are excluded from installer payloads. Rebuild the installer after packaging-rule changes; do not reuse an older staged payload. Installation rewrites application runtime paths, so staged binary hashes can differ from build-tree hashes. The normal `CPackConfig.cmake` retains the complete compatibility release gate and remains blocked while that contract is unmet.

Earlier [forecast validation](FORECAST_RELEASE_VALIDATION.md) and the [reporting baseline](RELEASE_VALIDATION.md) are historical evidence. Their test counts, performance measurements and package audits do not qualify the current installer; use the current validation record and its exact-package audit for this revision.
